# Qwen GPU stack: source check, 2026-10-17

**All notebook installs, GPU inference, quantization, adapter loading, memory fits and training below are UNTESTED here.** There is no local GPU. Web access worked. `source-verified` means inspected source or package metadata. `docs-verified` means an upstream statement. `inferred` means an estimate or proposed choice. Local CPU evidence is in validation notes (local scratch, not tracked).

## Inference install

- **source-verified:** Use the same candidate stack on Colab and Kaggle: Python 3.12, **vLLM 0.31.0, torch 2.13.0, Transformers 5.17.0**. vLLM requires torch exactly 2.13.0 and Transformers `>=5.10.4,<5.18.0`. Do not upgrade either alone. Current Transformers 5.20.1 is outside that range. Sources: [vLLM metadata](https://pypi.org/pypi/vllm/0.31.0/json), [Transformers release](https://pypi.org/project/transformers/5.17.0/), [vLLM release](https://github.com/vllm-project/vllm/releases/tag/v0.31.0).
- **source-verified:** The release's default wheel uses CUDA 13.0. Its separate **cu129** wheel exists for Linux x86_64. The tagged installation guide still says CUDA 12.9 is the default; use the release artifacts to resolve this conflict. Sources: [release assets](https://github.com/vllm-project/vllm/releases/tag/v0.31.0), [tagged guide](https://github.com/vllm-project/vllm/blob/v0.31.0/docs/getting_started/installation/gpu.cuda.inc.md).
- **docs-verified / inferred:** Select cu129 with driver R575 or newer for this pack. CUDA 12 minor compatibility can start at R525, but that does not guarantee new PTX/JIT kernels work. CUDA 13 requires R580 or newer. A notebook cannot replace its host driver. Stop on an older driver before model download. Sources: [NVIDIA compatibility limits](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html), [CUDA 12.9 release notes](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-toolkit-release-notes/index.html).
- **inferred, UNTESTED install recipe:** Create a fresh environment. These commands select matching CUDA 12.9 binaries. Run scripts with its interpreter; an already imported notebook torch will not change. Bootstrap `uv==0.13.1` with `python -m pip install uv==0.13.1` if needed. Sources: [uv release](https://pypi.org/project/uv/0.13.1/), [vLLM ABI guidance](https://docs.vllm.ai/en/v0.31.0/getting_started/installation/gpu.html), [torch wheel index](https://download.pytorch.org/whl/cu129/torch/).
```sh
uv venv gpu/.venv --python 3.12 --seed
uv pip install --python gpu/.venv/bin/python 'https://github.com/vllm-project/vllm/releases/download/v0.31.0/vllm-0.31.0+cu129-cp38-abi3-manylinux_2_28_x86_64.whl' 'torch==2.13.0+cu129' 'transformers==5.17.0' --extra-index-url https://download.pytorch.org/whl/cu129
uv pip check --python gpu/.venv/bin/python
```
- **inferred:** On an R580+ runtime, the shorter CUDA 13 alternative is `uv pip install --python gpu/.venv/bin/python vllm==0.31.0 torch==2.13.0 transformers==5.17.0`. Both recipes require a GPU import/load probe before being called working. Transitive dependencies are resolver-selected, so these are core pins, not a full reproducibility lock. Sources: [release](https://github.com/vllm-project/vllm/releases/tag/v0.31.0), [requirements](https://github.com/vllm-project/vllm/blob/v0.31.0/requirements/cuda.txt).
- **source-verified:** **Do not install external FLA or causal-conv1d for this inference recipe.** vLLM uses its vendored Flash Linear Attention (FLA) and convolution code. For the separate Transformers training environment, available pins are **flash-linear-attention 0.5.2** (with fla-core 0.5.2) and **causal-conv1d 1.7.0**. Build the latter against the selected torch with `--no-build-isolation`; a compatible wheel/compiler is still required. Sources: [vLLM DeltaNet imports](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py), [FLA release](https://github.com/fla-org/flash-linear-attention/releases/tag/v0.5.2), [convolution release](https://github.com/Dao-AILab/causal-conv1d/releases/tag/v1.7.0).
- **source-verified / docs-verified:** Text-only loading is supported: `LLM(..., language_model_only=True)` skips the vision tower. Merely disabling image inputs is a different control. Both generations use `Qwen3_5ForConditionalGeneration`. vLLM maps gate `swish` to `silu`; Transformers 5.17.0 has the family configuration and rotary fields. A config's saved Transformers version is not a minimum-version guarantee. Sources: [engine argument](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/engine/arg_utils.py), [official text-only recipe](https://github.com/vllm-project/recipes/blob/main/Qwen/Qwen3.5.md), [gate handling](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py#L483), [configuration](https://github.com/huggingface/transformers/blob/v5.17.0/src/transformers/models/qwen3_5/configuration_qwen3_5.py).
- **docs-verified / source-verified:** T4 first fails if bf16 is selected; use fp16. Standard FlashAttention 2 does not support Turing. The pack selects `TRITON_ATTN` on T4 and skips vision. DeltaNet still has its own kernels. P100 is SM60, below vLLM's SM75 minimum; treat it as **NO-GO for this pack**. Sources: [dtype check](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/platforms/cuda.py#L656), [FA2 hardware](https://github.com/Dao-AILab/flash-attention#nvidia-cuda-support), [vLLM hardware](https://docs.vllm.ai/en/v0.31.0/getting_started/installation/gpu.html), [NVIDIA GPU list](https://developer.nvidia.com/cuda-legacy-gpus).
- **docs-verified:** T4 reports include repeated cold compilation and stalls on vLLM 0.17/0.18. A contributor reports improvement on 0.28; this does not validate 0.31 on our notebooks. Eager mode in 0.31 disables JIT warmup, so a first request can include compilation. Sources: [issue 36589 and later comments](https://github.com/vllm-project/vllm/issues/36589), [issue 37175](https://github.com/vllm-project/vllm/issues/37175), [0.31 changes](https://github.com/vllm-project/vllm/releases/tag/v0.31.0).
- **source-verified:** Optional bnb-4bit now needs **vllm-bnb-plugin 0.0.3** plus **bitsandbytes 0.50.2**: install those pins in the same environment, then pass `--quantization bitsandbytes`. AWQ/GPTQ need a checkpoint in that format. Do not apply those names to unquantized weights. Offline FP8 checkpoints auto-detect; online FP8 now uses `--quantization fp8_per_tensor`, not `fp8`. Sources: [bnb plugin requirement](https://github.com/vllm-project/vllm/blob/v0.31.0/docs/features/quantization/bnb.md), [plugin metadata](https://pypi.org/project/vllm-bnb-plugin/0.0.3/), [bnb metadata](https://pypi.org/project/bitsandbytes/0.50.2/), [FP8 source](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/layers/quantization/fp8.py).
- **source-verified / inferred:** The sampler disables usage telemetry and FlashInfer artifact downloads. A missing external kernel must fail instead of making another network request. Model and tokenizer downloads remain allowed. This can expose a missing-kernel install on the first GPU session. Sources: [vLLM controls](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/envs.py), [FlashInfer download gate](https://github.com/flashinfer-ai/flashinfer/blob/v0.7.0.post1/flashinfer/jit/cubin_loader.py).
- **source-verified / inferred:** `--lora` passes a local adapter through `LoRARequest`, with rank ceiling 64. All formats, TP=2 and adapter targets remain UNTESTED. The pinned model maps GDN's fused projections and embedding targets. Earlier releases dropped targets or failed loading them. Use a new run directory after changing weights at the same model/adapter path. Sources: [current model mappings](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/models/qwen3_5.py), [historical target bug 38085](https://github.com/vllm-project/vllm/issues/38085), [embedding bug 48934](https://github.com/vllm-project/vllm/issues/48934).

## Memory feasibility: 10,240 total tokens per sequence, eight active sequences

- **inferred, all cells UNTESTED:** `Y` = plausible with room, `M` = marginal or kernel-dependent, `N` = do not budget for it. `F` = bf16, except fp16 on T4. `8` = FP8 weights. `Q` = substantially 4-bit AWQ, community GPTQ or bnb; loader support is a separate test. `G*` = the actual official partial-GPTQ checkpoint below. A cell lists `F/8/Q` in order, then `G*` if applicable. This is a memory estimate, not a benchmark. Sources: [model configurations](https://huggingface.co/Qwen/Qwen3.5-27B/blob/main/config.json), [hardware support matrix](https://docs.vllm.ai/en/v0.31.0/features/quantization/).

- **inferred:** Weight-only lower bounds are roughly `2N`, `N`, `N/2` bytes for 16/8/4-bit storage, before scales and unquantized layers. Real full-checkpoint sizes are **9.32 / 19.31 / 55.56 / 55.56 GB**. Text-only loading saves tower/MTP weights, but reserve room for workspaces and fragmentation. Sources: [4B index](https://huggingface.co/Qwen/Qwen3.5-4B/blob/main/model.safetensors.index.json), [9B index](https://huggingface.co/Qwen/Qwen3.5-9B/blob/main/model.safetensors.index.json), [27B index](https://huggingface.co/Qwen/Qwen3.5-27B/blob/main/model.safetensors.index.json), [3.8 index](https://huggingface.co/Qwen/Qwen3.8-27B/blob/main/model.safetensors.index.json).
- **inferred:** Full-attention KV bytes are `2 x full_layers x KV_heads x head_dim x tokens x sequences x dtype_bytes`. At 10,240 tokens and k=8, bf16 KV costs **2.50 GiB** for 4B/9B and **5.00 GiB** for either 27B. FP32 recurrent state adds about **0.375 / 1.125 GiB**, plus convolution state and allocator padding. Weight quantization does not shrink these caches. Sources: [4B dimensions](https://huggingface.co/Qwen/Qwen3.5-4B/blob/main/config.json), [27B dimensions](https://huggingface.co/Qwen/Qwen3.5-27B/blob/main/config.json), [vLLM state logic](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py).
- **source-verified / inferred:** The official 3.5-27B FP8 index stores **30.87 GB**. Its official GPTQ-Int4 stores **30.24 GB**, not 14 GB; substantial layers stay bf16. Neither is an L4 recommendation. A100 40 k=8 is marginal at the pack's 0.85 memory fraction. A100 80 bf16 is the safer 27B target. Sources: [FP8 index](https://huggingface.co/Qwen/Qwen3.5-27B-FP8/blob/main/model.safetensors.index.json), [GPTQ index](https://huggingface.co/Qwen/Qwen3.5-27B-GPTQ-Int4/blob/main/model.safetensors.index.json), [GPTQ exclusions](https://huggingface.co/Qwen/Qwen3.5-27B-GPTQ-Int4/blob/main/config.json).
- **source-verified / docs-verified:** FP8 compute is native on L4, not T4/A100. vLLM's FP8 path permits SM75+ and can select Marlin W8A16: FP8 weights with 16-bit activations. AWQ/GPTQ/bnb have different hardware paths. A hardware checkmark does not prove Qwen's GDN shapes work. Sources: [FP8 implementation](https://github.com/vllm-project/vllm/blob/v0.31.0/vllm/model_executor/layers/quantization/fp8.py), [quantization matrix](https://github.com/vllm-project/vllm/blob/v0.31.0/docs/features/quantization/README.md), [historical narrow-projection bug 35924](https://github.com/vllm-project/vllm/issues/35924).
- **inferred:** `M` cells often permit k=1 or shorter output caps. `n=8` requests eight samples; it does not guarantee eight long sequences remain resident together. The engine can schedule fewer. Two T4s use TP=2; they do not become one 32 GB device, and each needs workspace. The pack reserves 80% below 20 GiB per GPU and 85% otherwise. Sources: [engine memory controls](https://docs.vllm.ai/en/v0.31.0/configuration/engine_args/), [hybrid cache design](https://docs.vllm.ai/en/v0.31.0/design/hybrid_kv_cache_manager/).
- **inferred, UNTESTED k=1 estimates at 10k:** 16-bit 4B is plausible on every target. 16-bit 9B needs 2xT4, L4 (marginal), or A100. Either 27B in 16-bit needs A100 80. The official 27B FP8/partial-GPTQ weights need A100 40/80 even for k=1. More complete 4-bit quantization may permit a 27B k=1 load on L4 or 2xT4; single T4 is not a budget target. 4B/9B 4-bit loads are plausible on all targets, subject to kernel support. A 9B FP8 load on single T4 remains marginal. Use detected bytes, not the nominal GPU label. Sources: [base weight sizes](https://huggingface.co/Qwen/Qwen3.5-9B/blob/main/model.safetensors.index.json), [27B quantization size](https://huggingface.co/Qwen/Qwen3.5-27B-GPTQ-Int4/blob/main/model.safetensors.index.json), [cache dimensions](https://huggingface.co/Qwen/Qwen3.5-27B/blob/main/config.json).
- **source-verified / inferred:** The checked 4B and 3.8 tokenizer configs mark `</think>` as non-special, so default special-token removal should preserve it. GPU detokenization remains UNTESTED. Metadata records closure and truncation counts for the latest generating invocation. Closure is informative in think mode; nothink includes the required saved prefix. Sources: [4B tokenizer config](https://huggingface.co/Qwen/Qwen3.5-4B/blob/main/tokenizer_config.json), [3.8 tokenizer config](https://huggingface.co/Qwen/Qwen3.8-27B/blob/main/tokenizer_config.json).
