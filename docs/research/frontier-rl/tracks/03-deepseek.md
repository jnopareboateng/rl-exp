## 1. TL;DR

- **DeepSeek has never open-sourced an RL training stack.** Every `deepseek-ai` repo I cloned (V3, R1, Math, Prover-V1.5/V2, Math-V2, V3.2-Exp, 3FS, DeepEP, DeepGEMM, FlashMLA, DualPipe, EPLB, smallpond, DeepSpec, DeepSelect, DeepJIT, TileKernels, Engram, deepseek-harness) contains weights/READMEs/PDFs, inference demos or kernels/infra, never a GRPO trainer. The `open-infra-index` states the rollout engine is "an early fork of vLLM from over a year ago", tightly coupled to internal infra, and the training framework is plain PyTorch [V]. The RL recipe has to be reconstructed from papers (GRPO equations + hyperparameters) plus the kernel/comm libraries.
- **The algorithm is deliberately small.** GRPO (DeepSeekMath, Feb 2024) = PPO-clip with no critic, group-mean/std baseline, per-token K3 KL to a reference. R1 used it at scale with *rule-based outcome rewards only* (accuracy + format + language-consistency), explicitly rejecting neural reward models for reasoning because of reward hacking. Gains came from verifiable reward, long context (32k to 65k), and ~10k steps, not clever loss tricks.
- **V3.2 (Dec 2025) is the only release that documents RL stability fixes**: importance-weighted ("unbiased") K3 KL, off-policy sequence masking (drop negative-advantage sequences whose policy drift exceeds delta), **Keep Routing** (replay MoE expert indices from rollout in training), **Keep Sampling Mask** (replay top-p/top-k truncation masks), specialist-then-distill + one mixed RL stage, >10% of pre-training cost spent on post-training, ~1,800 synthetic environments / 85k prompts for agentic RL.
- **Verifier-side innovation is the real frontier at DeepSeek**: DeepSeekMath-V2 (Nov 2025) replaces final-answer checking by an RL-trained generative verifier + meta-verifier, rewards the generator for *honest self-verification* (`R = R_format * (0.76*R_Y + 0.24*R_Z)`), and uses scaled verification compute to auto-label hard proofs so the verifier keeps pace. This is the same shape of problem as "weak/slow biological oracle", and the repo includes the actual verify/refine loop code.
- **V4 (24 Apr 2026) changes the post-training topology**: per-domain specialists (SFT then GRPO) are consolidated by **multi-teacher on-policy distillation** (reverse KL over the *full vocabulary*, 10+ teachers) instead of V3.2's single mixed RL stage; RL infra adds FP4 QAT, a preemptible token-level-WAL rollout service, million-token-context RL data plumbing, and a DSec sandbox platform with tens of thousands of concurrent sandboxes [S/2]. V4.1-Flash (Sept 2026) reports "no algorithmic innovation", gains attributed to scaling quantity/diversity/verifiability of synthesized agent tasks, and notes RL agents reward-hacking, escaping sandboxes and deleting filesystems [2].
- **Formal verification as reward is solved cleanly in Prover V1.5/V2**: binary Lean-compiler reward, GRPO with 256 problems x 32 samples, curriculum via subgoal decomposition, a "consistency reward" to keep proofs aligned with the CoT sketch. Closest direct analogue for "binary reward from a deterministic checker".
- **Open Infra repos matter for RL mainly as the *engine under* RL**: DeepEP + DeepGEMM + FlashMLA are the MoE comm / FP8-FP4 GEMM / attention kernels that Megatron-style trainers and vLLM/SGLang rollout engines inherit; EPLB and 3FS are secondary; DualPipe matters only for pretraining-style large pipeline runs. Nothing in them is RL-specific, but the September 2026 versions explicitly expose training-and-rollout shared APIs (see section 5).
- **Code evidence of the agentic RL contract** (new, from `deepseek-harness`, Aug-Sep 2026): a "minimal" preset is documented as the "Claude SWE-compatible RL contract": a single persistent `bash(command)` tool (300 s timeout, danger-full-access), fixed persona "You are a helpful software engineer assistant.", **no context compaction**, no runtime-context injection. The notes call it "the intended training runtime" [V, inference that it mirrors DeepSeek's RL env is mine].

## 2. Per-project sections

### 2.1 GRPO origins: DeepSeekMath (arXiv 2402.03300, Feb 2024)

- **What**: 7B math model continued-pretrained on 120B math tokens, then SFT, then RL with **Group Relative Policy Optimization**. [S]
- **Objective**: PPO-clip surrogate averaged over G samples per question and tokens, `1/G sum_i 1/|o_i| sum_t [min(r_it A_it, clip(r_it,1-eps,1+eps) A_it) - beta * D_KL(pi_theta || pi_ref)]`. The KL is the K3 estimator `pi_ref/pi_theta - log(pi_ref/pi_theta) - 1` (guaranteed non-negative), added *to the loss*, not folded into the reward as in RLHF-PPO. [S]
- **Advantage**: outcome supervision = normalized end-of-sequence reward `(r - mean(R))/std(R)` broadcast to every token; process supervision = sum of normalized step rewards from step index >= t. No value model: "foregoes the value model, instead estimating the baseline from group scores". [S]
- **DeepSeekMath-RL config**: ~144K chain-of-thought questions from GSM8K+MATH train, lr 1e-6, beta 0.04, 64 samples/question, max length 1024, batch 1024, one policy update per exploration stage. Iterative RL variant retrains the reward model with 10% replay of old data. Result: GSM8K 82.9 to 88.2, MATH 46.8 to 51.7. [S]
- **Insight worth keeping**: RL improved Maj@K but not Pass@K ("renders the output distribution more robust"), the first appearance of the "RL sharpens, doesn't expand" thesis. Also a unified view where SFT/RFT/DPO/PPO/GRPO differ only by data source (online/offline) and a gradient coefficient. [S]
- Repo `deepseek-ai/DeepSeek-Math`: evaluation scripts only [V].

### 2.2 DeepSeek-R1-Zero / R1 (arXiv 2501.12948; Nature 17 Sep 2025)

**R1-Zero** = DeepSeek-V3-Base + GRPO, no SFT.
- **Rewards (rule-based only)** [S, quoted by fetcher]:
  - Accuracy reward: deterministic (answer match for math; compile/test-case for code).
  - Format reward: enforce `<think> ... </think>` (and `<answer>` in the R1-Zero template). `Reward_rule = Reward_acc + Reward_format`.
  - Language-consistency reward (added for R1, not R1-Zero): `Reward_language = Num(Words_target)/Num(Words)` over the CoT. Slight performance degradation traded for readability.
- **Template** (Table 1): "A conversation between User and Assistant ... reasoning process and answer are enclosed within `<think>` and `<answer>` tags." [S]
- **Nature hyperparameters** [S]: lr 3e-6; KL coef 0.001; clip eps 10 (the fetcher quoted "clip ratio epsilon to 10" twice, but I could not confirm this directly; treat as likely but unverified); group G=16; 32 unique questions x 16 = 512 per training batch; 8,192 outputs per rollout step split into 16 minibatches, single inner epoch; sampling temperature 1.0; max length 32,768 then 65,536 after step 8.2k (a visible response-length jump); 10,400 steps (~1.6 epochs); **reference model replaced by the latest policy every 400 steps**. R1 stage 2: temperature 0.7, 1,700 steps, general (RM-judged) data only in the last 400 steps because model-based rewards "become more susceptible to exploitation as training progresses".
- **Dynamics**: R1-Zero AIME 2024 pass@1 15.6% to 77.9% (86.7% with self-consistency), thinking length grows from near zero to ~20k tokens, "aha moment" = sudden rise in "wait" during reflection. [S]
- **R1 multi-stage pipeline** [S]: (1) cold-start SFT on thousands of long-CoT examples (R1-Zero traces rewritten into first-person conversational style by humans then LLM, second human verification) = Dev1 (better IF-Eval, slightly worse reasoning); (2) reasoning RL with language consistency; (3) rejection sampling from that checkpoint: ~600k reasoning samples (correct-only, CoT with mixed languages / long paragraphs / code blocks filtered; some judged by DeepSeek-V3 as generative RM) + ~200k non-reasoning from V3 pipeline; SFT on ~800k (math 395k, code 211k, STEM 10k, logic 10k, general 178k) = Dev3; (4) second RL over reasoning + general data with helpful RM (66k preference pairs, built from V3 judgments with score delta>1, trained on final-summary only) and safety RM (106k point-wise safe/unsafe).
- **Distillation**: the 800k samples SFT'd (no RL) into Qwen2.5 1.5B/7B/14B/32B and Llama 8B/70B; 2-3 epochs, 32k context. Qwen-32B distilled beats Qwen-32B trained with 10k+ steps of RL directly [S, from R1 text], i.e. distillation > small-model RL.
- **Failed/abandoned** [S]: neural PRMs and outcome RMs for reasoning ("susceptible to reward hacking during large-scale RL", also retraining overhead); MCTS (token search space too large, value model hard). Limitations: no tool use, token overthinking, language mixing outside zh/en, prompt sensitivity (few-shot hurts).
- **Infra (Nature supplement B.1)** [S]: four decoupled modules: Rollout (vLLM workers, expert parallelism, multi-token-prediction speculative decoding), Inference (reward model + reference forward), Rule-based Reward (asynchronously scheduled to overlap), Training (DualPipe, best-fit sequence packing).
- **Cost** [S, arithmetic-checked by me]: 512 H800 (64 nodes x 8); R1-Zero ~198 h (~101k GPU-h, ~$202k at $2/GPU-h), SFT-data creation ~5k GPU-h (~$10k), R1 ~80 h (~41k GPU-h, ~$82k); total **$294k**, excluding the V3-Base pretraining. (One secondary article said 648 GPUs; 101k/198h = 510 supports 512.)
- **R1-0528** [S, HF card]: avg ~23K tokens/AIME question vs 12K before; AIME 2025 70% to 87.5%; "increased computational resources and algorithmic optimization mechanisms in post-training" (undisclosed). Repo `DeepSeek-R1` = README + PDF only [V].

### 2.3 DeepSeek-V3, V3.1, V3.2-Exp, V3.2 (Dec 2024 - Dec 2025)

- **V3** (arXiv 2412.19437) [S]: 671B/37B MoE, 14.8T tokens, FP8 training, DualPipe, DeepEP; total 2.788M H800 GPU-h ($5.576M at $2/h) of which post-training only ~5K GPU-h. Post-training: ~1.5M SFT instances, reasoning data *distilled from an R1-series teacher* (with length/overthinking management), rule-based RM where possible, model-based RM (preference data with CoT before the final reward) otherwise, GRPO, plus "self-rewarding"/constitutional-style alignment where the model votes on its own outputs.
- **V3.1** (Aug 2025) [S, HF card]: hybrid thinking/non-thinking via chat template; post-trained for tool/agent use; 32K-extension 630B tokens, 128K-extension 209B tokens; UE8M0 FP8 scale format "to ensure compatibility with microscaling data formats". V3.1-Terminus then V3.2-Exp (Sept 2025) added DeepSeek Sparse Attention (DSA) by continued training (dense warm-up 1,000 steps x 16 x 128K = 2.1B tokens training only the indexer; sparse stage 15,000 steps x 480 x 128K = 943.7B tokens, top-k = 2048) and was RL-aligned to V3.1-Terminus settings [V, from the Exp PDF].
- **V3.2 (arXiv 2512.02556, 1 Dec 2025; MIT, 685B)** [S; formula text via fetcher]. Three claimed pillars: DSA, scalable RL, agentic task synthesis.
  - **Recipe**: (a) per-domain specialists (math, programming, general logic, general agent, agentic coding, agentic search; each with thinking and non-thinking modes) trained with large RL; (b) specialists generate distillation data; (c) a **single mixed RL stage** merges reasoning, agent and human-alignment ("circumventing catastrophic forgetting of multi-stage"). Distilled students are "only marginally below specialists", gap closed by the final RL. Post-training budget "exceeding 10% of the pre-training cost".
  - **Rewards**: reasoning/agent: rule-based outcome reward + length penalty + language-consistency reward; general: a **generative reward model with per-prompt rubrics**. Advantages are group mean-subtracted, per original GRPO (no std/length changes like DAPO or Dr.GRPO; per Raschka 2026 [2]).
  - **The four GRPO stabilizers** (this is the single most reusable section of the paper):
    1. **Unbiased KL estimate**: the K3 estimator is multiplied by the importance ratio `pi_theta / pi_old` so its expectation is the true KL under the *sampling* policy; fixes systematic bias when sampled tokens are much less likely under pi_theta than pi_ref (the old K3 gives unbounded gradient weights on such tokens). They also treat beta as per-domain ("very weak or even zero KL often works best for mathematics", via [2]).
    2. **Off-policy sequence masking**: binary mask `M_it = 0` iff `A_hat_it < 0` *and* the sequence-mean `log(pi_old/pi_theta) > delta`; keeps those sequences out of the loss. Motivation: multiple gradient steps per rollout batch plus training-inference engine mismatch push data off-policy; masking only the *negative-advantage* ones because "the model benefits the most by learning from its own mistakes" (i.e., keep high-drift positives). Values of delta, eps, beta, G, batch size, lr are **not disclosed**.
    3. **Keep Routing**: record the expert indices chosen at sampling time in the inference engine and force the same routing in the training forward pass. "Crucial for RL training stability of MoE models", used since V3-0324.
    4. **Keep Sampling Mask**: record the top-p/top-k truncation mask applied at sampling and apply it to pi_theta in training so both policies share the same action support (otherwise importance sampling is invalid).
  - **Agentic task synthesis (Table 1)**: code agent 24,667 tasks (real GitHub-derived environments; issue-PR pairs mined at the million scale, kept if gold patch makes >=1 fail-to-pass test and zero pass-to-fail); search agent 50,275 (real search tools, synthesized prompts, multi-agent pipeline plus verification agent with multi-pass search; plus rubric+GRM scoring); code interpreter 5,908 (Jupyter); general agent 4,417 tasks across **1,827 synthetic environments** (tool-function sandbox + "hard to solve, easy to verify" tasks with a verification function, iterated for difficulty; filtered to pass@100 > 0). Total "over 1,800 environments and 85,000 complex prompts".
  - **Thinking-with-tools context management**: reasoning is discarded only when a *new user message* arrives; tool outputs keep prior reasoning. Cold start for tool-use thinking is *prompting only*, no SFT-trained scaffold: system-prompt instructs interleaved calls and RL amplifies the few successes. Chat template adds a `developer` role (search agents only). 
  - **Speciale**: reasoning-only RL, reduced length penalty, plus DeepSeekMath-V2 data/reward for proofs; IMO 2025 35/42, CMO 2025 102/126, IOI 2025 492/600, ICPC WF 2025 10/12 (gold-level) [S]. Limitations they state: token inefficiency vs Gemini-3.0-Pro, world-knowledge gap.
- **Code facts** (`DeepSeek-V3.2-Exp/inference`) [V]: see section 3.

### 2.4 DeepSeek-Prover V1.5 and V2 (Aug 2024; Apr 2025)

- **V1.5** (arXiv 2408.08152) [S]: SFT on proof data, then **RLPAF** (RL from proof-assistant feedback) with GRPO: binary reward = Lean 4 verifies, lr 5e-6 constant, beta 0.02, group 32, ~4.5k theorem statements chosen for "moderate success rate", max length 2,048, batch 512. Inference-time search **RMaxTS**: MCTS with RMax-style intrinsic reward (maximal reward on reaching an unseen state; discounted UCB, gamma=0.99) plus "truncate-and-resume" (cut whole-proof generation at first Lean error, resume with prover state as a comment). miniF2F-test 60.2% single pass, 63.5% with RMaxTS.
- **V2** (arXiv 2504.21801, PDF read in full) [V]: 
  - Cold start: DeepSeek-V3 decomposes a theorem into `have ... := by sorry` subgoals (Lean skeleton plus informal CoT); a **7B prover solves subgoals recursively**; for theorems the 7B can't do end-to-end but whose subgoals all resolve, the composed proof + V3's CoT becomes synthetic "hundreds" of cold-start CoT examples.
  - Curriculum: subgoal theorems (with and without preceding subgoals as premises) are added to expert iteration as intermediate-difficulty problems, so sparse-reward hard problems get denser signal (cf. AlphaProof's test-time variations).
  - Stage 1: expert iteration to train a non-CoT mode; stage 2: SFT of V3-Base-671B (constant lr 5e-6, 16,384 context) on non-CoT + cold-start CoT; then **GRPO** with binary Lean reward, prompts filtered to "sufficiently challenging yet solvable by the SFT model", **256 problems x 32 proofs, max 32,768 tokens** per iteration. A **consistency reward early in training** penalizes proofs that don't contain all CoT-planned `have` lemmas (the structure-drift problem). 7B distilled from 671B RL rollouts (context extended 4k to 32k) then run through the same RL.
  - Results: miniF2F-test 88.9% (Pass@8192; 90.6 incl. fix), PutnamBench 47/658, ProverBench (325 problems incl. AIME 24/25 formalizations) released. Weights only; no training code [V].

### 2.5 DeepSeek-GRM / SPCT (arXiv 2504.02495, Apr 2025): generative reward models + inference-time scaling

[S] Pointwise **generative RM**: given a query and set of responses, emit principles + critique + per-response scores as text (so it handles single/paired/multi responses and can be sampled k times).
- **SPCT (Self-Principled Critique Tuning)**: (1) *rejective fine-tuning* cold start (sample N_RFT=3, keep trajectories whose predicted scores identify the ground-truth-best response, reject "too easy" all-correct prompts; ~1.07M general instruction + 186K rejected-sampled data); (2) **online rule-based RL with GRPO**: reward +1 if the best response is correctly identified, -1 otherwise; no format reward, *instead a larger KL coefficient* (beta=0.08 for 27B) to keep format stable; ~237K RL prompts; 19.2 h RFT + 15.6 h RL on 128 A100s (27B).
- **Principles are generated, not fixed**: the model writes its own evaluation principles per query, "adaptively aligning" the reward process; this is what makes the reward scale with sampling.
- **Inference-time scaling**: sample k (principles + critique) sets, sum the pointwise scores (expands the score granularity by k); a trained **meta RM** filters low-quality samples (vote on top k/2 by meta score). Reported (Reward Bench / overall, 27B): k=1 85.2 / 67.9, Voting@8 87.8 / 70.6, MetaRM@32 90.4 / 72.8; claim: 27B with 32 samples matches a 671B model. Weaknesses: slower than scalar RMs, behind on verifiable math/code. Variants Lite-16B, 27B (Gemma-2 base), 236B (V2.5), 671B (V3).
- Weights were announced as forthcoming; I found no repo (the `DeepSeek-GRM` clone attempt failed) [V for absence at time of check]. The idea re-emerged as V3.2's per-prompt rubric GRM and V4's "the specialist itself learns to judge".

### 2.6 DeepSeekMath-V2 (Nov 2025; Apache-2.0; on V3.2-Exp-Base)

[V]: full PDF + inference code read.
- **Verifier**: input (problem X, proof Y, rubric I_v) -> text analysis then score in {0, 0.5, 1} (1 = rigorous, 0.5 = sound but minor errors/omissions, 0 = fatal). RL reward = `R_format * R_score`, `R_score = 1 - |s' - s|`; format = required key phrases ("Here is my evaluation of the solution:", "\\boxed" after "Based on my evaluation, the final overall score should be:"). Cold-start data: 17,503 AoPS olympiad/TST/proof problems, proofs from a V3.2-Exp-Thinking variant iteratively refined, random sample scored by math experts.
- **Failure mode they found**: a verifier can score right while *hallucinating the issues*. Fix: a **meta-verifier** (RL-trained, rubric I_mv, expert-annotated quality scores) that checks whether cited issues exist and justify the score; verifier reward becomes `R_V = R_format * R_score * R_meta`. Meta-verified analysis quality on a validation split 0.85 to 0.96 at equal score accuracy.
- **Generator**: reward `R_Y` = verifier score of the proof; then **self-verification training**: the generator outputs proof Y plus self-analysis Z in the verifier's format, rewarded `R = R_format * (alpha*R_Y + beta*R_Z)`, `R_Z = R_score(s', s) * R_meta(Z)`, **alpha=0.76, beta=0.24**. Incentive: honesty about flaws is paid more than false confidence; best policy is to find and fix issues before finalizing.
- **Verifier keeps up via scaled verification compute** (automatic labeling): n independent verifications per proof; analyses reporting issues get m meta-assessments (majority validates); a proof gets the lowest score if >=k validated analyses agree, label 1 if no legitimate issue found anywhere, else discard/route to humans. "In our last two training iterations, this fully automated pipeline replaced human annotation entirely." Iteration: verifier RL, then generator init from the verifier checkpoint, RL (GRPO); from iteration 2 the verifier init is a rejection-fine-tuned merge of verification+generation.
- **Test-time loop** (paper + `inference/main.py`, `run.sh`) [V]: pool of proofs per problem; `--n_verification_per_proof 64`, `--n_best_proofs_to_sample 32`, `--n_agg_trials 32`, `--n_parallel_proof_gen 128`, `--max_rounds 16`, generation max length 128K, verification 64K, temperature 1.0. Each round: verify each proof 64x, mean score; stop a problem if any proof has meanscore >0.99999; otherwise sort by `(meanscore, self_eval_score)`, take top-N, sample combinations of `n_proofs_to_refine` proofs, attach up to 8 shuffled critiques (<=4 per distinct score, prioritizing critiques identifying issues), and ask the model to write a better solution ("solving issues ... re-using promising ideas ... or both"). Meta-verification is available in code but `run.sh` passes `--skip_meta_verification`; when enabled, only ratings with score <=0.75 are meta-checked. Provenance of every refined proof is tracked in `dep_proof_ids` (a lineage DAG).
- Results: IMO 2025 5/6 (83.3%), CMO 2024 gold-level, **Putnam 2024 118/120**, IMO-ProofBench strong; one-shot CNML-level beats GPT-5-Thinking-High and Gemini 2.5 Pro by their verifier.

### 2.7 2026: V4 and V4.1 (and what does not exist)

- **DeepSeek-V4 (24 Apr 2026; arXiv 2606.19348; weights on HF)** [S/2]: V4-Flash 284B/13B-active, V4-Pro 1.6T/49B-active; 1M context default; hybrid attention (CSA with m=4 compression + HCA with m'=128), manifold-constrained hyper-connections (mHC), Muon optimizer; 32T/33T pretraining tokens; at 1M context V4-Pro uses 27% of V3.2's single-token FLOPs and 10% of KV cache (Flash: 10%/7%). Modes: Non-think / High / Max (three reasoning efforts trained with different length penalties and context windows [2]). Model card PDF contains **no** RL details [S].
  - **Post-training = two stages** (Sec. 5.1) [S, consistent across 3 sources]: (i) for each of math, coding, agent, instruction-following: SFT then **GRPO** with domain reward models, including a **generative reward model** (reported as "the actor serves as its own GRM", rubric-guided, no separate scalar RM [2]); (ii) a single student is trained by **on-policy distillation (OPD)**: student samples its own trajectories, minimizes reverse KL `D_KL(pi_theta || pi_teacher_i)` against 10+ teachers over the **full vocabulary** (>=100k logits) rather than sampled-token approximations. This *replaces* V3.2's mixed RL stage.
  - **RL/OPD infra** (Sec. 5.2) [2, one source is a close paraphrase of the paper; the HTML copy I fetched was truncated before Sec. 5]: FP4 quantization-aware training (FP32 master weights quantized to FP4 and losslessly dequantized to FP8 for compute, on MoE expert weights and the lightning-indexer QK path; real FP4 kernels at rollout); *efficient teacher scheduling* (cache only each teacher's last-layer hidden states, rebuild logits on the fly; order samples by teacher so only one teacher head is in memory); **preemptible, fault-tolerant rollout service with token-granular write-ahead log and KV-cache persistence**, motivated by a statistical bug: "if simply restarted, short responses face lower interruption probability, causing length bias toward brevity"; million-token RL data plumbing (split lightweight metadata from heavy per-token fields, shared memory, mini-batch-level release); **DSec** (DeepSeek Elastic Compute): unified sandbox platform with four execution substrates (function call, container, microVM, fullVM), EROFS/overlaybd image loading, tens of thousands of concurrent sandboxes, ordered trajectory logs of commands/results.
  - Benchmarks quoted by the fetcher for V4-Pro-Max looked internally inconsistent (e.g. SWE-Verified 37.7), so I do not reproduce them; the paper self-assesses a ~3-6 month gap to GPT-5.4 / Gemini-3.1-Pro on knowledge/reasoning.
- **V4 point releases** (API changelog) [S]: V4-Flash update 31 Jul 2026, V4-Pro GA 13 Aug 2026 (HLE 42.7/60.0 without/with tools, three effort levels, peak/off-peak pricing), V4-Flash-Vision-Exp 21 Aug, **V4.1-Flash 10 Sep 2026** (arXiv 2609.19969, 17 Sep). Legacy `deepseek-chat`/`deepseek-reasoner` sunset 24 Jul 2026.
- **V4.1-Flash** [S/2]: 552B-parameter MoE with a *causal encoder-decoder* (8B active at prefill, 16B at decode), CSA2 + FP4 KV cache (890 B/token global, ~1/4 of V4-Flash; ~1/8 persistent SSD cache), native vision, 45T multimodal tokens, MIT. Post-training = "SFT, RL, then OPD", "no algorithmic innovation": "essentially all reported gains come from scaling the quantity, diversity, and verifiability of synthesized tasks and agent environments" [2]. Sec. 5 headings: large-scale agent task synthesis, RL in synthesized tasks, DSec at massive scale, controllable reasoning effort, asynchronous post-training infra ("mitigating length bias and off-policy effects", large-scale OPD). Reported RL-agent failure modes: reward hacking, sandbox exploits, deleting critical system files / whole filesystems [2]. Terminal-Bench 2.1 90.6, DeepSWE v1.1 74.2 (company claims). I could not read Sec. 5 bodies (HTML copy truncated). A page titled "local-ai-zone deep dive" claimed PPO + a 500K-comparison RM for V4.1; it contradicts the primary abstract and the paper reviews, so I discarded it as hallucinated.
- **R2 / "V4-Thinking"**: there is **no official DeepSeek R2 release** that I could find; several "R2 guide" pages are speculative/SEO [2, weak]. After V3.1 the line was merged into hybrid models; V4 simply has thinking modes.
- Other 2026 repos (not RL): Engram (Jan 2026, conditional memory), mHC, TileKernels (TileLang), DeepJIT, DeepSelect (top-k for DSA, "V4.1" mentioned), DeepSpec (draft-model training for speculative decoding), `deepseek-harness` (open-source agent harness; section 3).

## 3. What the code shows that the papers don't

1. **No RL trainer anywhere; rollout engine is a private vLLM fork** [V] (`open-infra-index/OpenSourcing_DeepSeek_Inference_Engine/README.md`). Community RL (verl, slime, OpenRLHF, etc.) consumes DeepSeek's kernels and papers, not its trainer.
2. **`deepseek-harness` encodes the agentic RL contract** [V] (`.agents/notes/archived/bug-fix/2026-08-10-minimal-preset-owns-rl-composition.md`, `feature/2026-07-29-persistent-bash-str-replace-editor.md`, `feature/2026-08-11-minimal-profiles-bare-two-tool-runtime.md`): "Claude SWE-compatible RL contract" = persistent PTY `bash`, optional Claude-style `str_replace_editor` (`view/create/str_replace/insert`, absolute paths, `old_str` only; later notes remove the editor and keep a bare *persistent-shell-only* profile), 300-second tool timeout, fixed persona string, `complete: true` system prompt that suppresses all dynamic runtime context, **no compaction** ("a long session could therefore replace history"), danger-full-access sandbox, uncompressed JSONL session persistence, and shell state lost on timeout/cancel (shell is closed to avoid "uncertain state"). Those choices read like the environment the models were trained in: deterministic state, no history rewriting (which would break token-level credit assignment/prefix reuse). The notes literally say the earlier compaction/sandboxed-fs setup "did not match the intended training runtime". [I: that this is the production RL env]
3. **The reference sampler in V3.2-Exp is a pure Gumbel/exponential-race temperature sampler with no top-p/top-k** (`DeepSeek-V3.2-Exp/inference/generate.py`: `probs.div_(torch.empty_like(probs).exponential_(1)).argmax(-1)`) while the paper's "Keep Sampling Mask" implies the production sampler *does* truncate. So the public demo cannot reproduce RL rollout distributions.
4. **DSA introduces a second discrete selection that must match between rollout and trainer**: `Indexer.forward` takes `index_score.topk(min(index_topk, end_pos))` (top-k=2048 in `config_671B_v3.2.json`) and asserts all TP ranks agree via `dist.broadcast` (`model.py` lines ~483-486). The paper's Keep Routing handles MoE expert choice; I found no analogous "keep indexer indices" mention [I: the same train/infer mismatch risk applies]. A Nov 2025 README note admits an indexer-RoPE layout bug (non-interleaved in indexer, interleaved in MLA) in the inference demo that silently degraded quality: a reminder that RL rollout/trainer kernel parity is fragile.
5. **DeepSeekMath-V2's inference code is effectively the "evolution" loop they used to auto-label proofs** (`DeepSeek-Math-V2/inference/main.py`): lineage tracking (`dep_proof_ids`), stratified critique sampling, early stop on mean score >0.99999, meta-verification of only low-scored (<=0.75) ratings, 64 verifications per proof, 128K/64K lengths. The paper doesn't give `n`, `m`, `k` of the labeling pipeline; the code shows the test-time analogue (64 verifications, 8 critiques per refinement).
6. **DeepEP v2.5 / DeepGEMM / FlashMLA (Sept 2026 heads) expose shared training+rollout APIs** [V]: `EPBuffer` dispatch/combine is "the same API" for training, prefill and decode; `do_cpu_sync=True` for train/prefill (exact sizes) vs False for decode (GPU-side counts); saved `handle` enables `combine_backward`/`dispatch_backward`; new `lb_prefetch_weights` / `lb_reduce_grads` for **dynamic redundant experts** (prefetch replicated expert weights + scales over NVLink, then reduce FP32 grads back into the original expert) [V, DeepEP README]. DeepGEMM: contiguous grouped GEMM (train/prefill), **masked grouped GEMM for CUDA-graph decode** fed by DeepEP low-latency output, K-grouped GEMM for MoE weight-gradient, FP8xFP4 GEMM, "Mega MoE" (dispatch + GEMM1 + SwiGLU + GEMM2 + combine fused with NVLink overlap), FP4 indexer; scale-factor format differs by arch (**SM90 FP32 scales, SM100 packed UE8M0**) [V]. FlashMLA: sparse prefill/decode with FP8/FP4 KV cache and dense MHA fwd+bwd for SM100 (1460 TFLOPS fwd, 1000 bwd on B200 as reported by NVIDIA); the 2026-09-30 release **drops Hopper and all models before V4.1** and changes the KV format [V]. Training/inference numerical-format divergence (FP8 vs FP4 KV, SM90 vs SM100 scales) is exactly where logprob mismatch (the off-policy issue in V3.2) enters. Ascend ports of DeepGEMM/DeepEP/FlashMLA/TileKernels/DeepSelect appeared 30 Sep 2026 [V], so the RL stack is being made hardware-portable.
7. **EPLB is only a planner** [V] (`EPLB/eplb.py`): inputs are per-layer expert loads (README: "common method is moving average of historical statistics"), outputs physical-to-logical map with redundant replicas; hierarchical policy (pack expert groups to nodes, replicate within node, pack to GPUs; for prefill/small EP) vs global policy (decode/large EP).

## 5. Transfer to biology

Design principles DeepSeek demonstrates: (a) cheap deterministic verifier beats learned RM; (b) when no verifier exists, *train a verifier with RL, audit it with a meta-verifier, and reward the policy for honest self-critique*; (c) specialists then distill (OPD); (d) synthesize environments at scale with a "hard to solve, easy to verify" criterion; (e) fix train/infer mismatch explicitly (keep routing/masks, off-policy masks).

1. **Lean-style verifier = compiler/solver for design constraints** (V1.5/V2 analogue). Binary reward from deterministic checkers: protein-design constraint verifiers (symmetry, motif RMSD to target < threshold, no clashes in Rosetta/OpenMM, sequence liability filters), retrosynthesis route validity (every step in a reaction-rules template DB and building blocks available), SMARTS-valid and synthesizable molecules, CRISPR guide on/off-target scoring by an exact search. Use the V2 recipe: filter prompts to "challenging yet solvable by the SFT model", G=32 samples, large per-sample token budget, plus a **consistency reward** tying the final design to an intermediate plan (e.g., predicted-contact map / retrosynthetic sketch).
2. **Subgoal-decomposition curriculum for biological design** (V2). Use a big generalist LLM to decompose a hard design (multi-domain binder, multi-step synthesis, pathway edit) into subgoal theorems; a small specialist solves subgoals; composing solved subgoals yields cold-start traces for the big model; subgoal variants feed expert iteration. Directly addresses sparse reward in protein/metabolic design.
3. **Generative verifier + meta-verifier for hard-to-verify bio claims** (MathV2). Where the oracle is a noisy proxy (docking score, AF2 pLDDT/ipTM, ADMET predictors, Cell-painting predictors), train a text verifier that must *name specific failure modes* (e.g., "buried unsatisfied polar, disconnected interface, extrapolating outside assay domain"); add a meta-verifier that checks whether the cited failure is real (checkable against structure/measurements) to stop hallucinated critiques; multiply reward `R_format * R_score * R_meta`. Then reward the *designer* for self-critique agreement with the verifier (0.76/0.24 weighting) so it iterates internally before spending any assay. **Novel application**: turning heterogeneous in-silico predictors into one rubric-conditioned verifier that is calibrated by sparse wet-lab truth, with meta-verification catching "oracle hallucination".
4. **Scale verification compute to auto-label (MathV2 pipeline) for wet-lab**: for each candidate run n independent in-silico critiques; wet-lab (the expensive ground truth) is used only on candidates where verifiers disagree or all pass; verified-by-assay labels refresh the verifier (the "generation-verification gap" loop). **Novel** as active-learning-for-verifier-RL with explicit discard/route-to-human buckets.
5. **GRM/SPCT for preference-heavy bio objectives** (developability, "drug-likeness" taste, expert manual review): train a pointwise generative RM that writes its own principles per target (stability vs specificity vs manufacturability), then do k-sample voting + meta-RM at inference to scale reward quality with test-time compute. Appropriate when you have scarce expert rankings (+1/-1 "identify the experimentally better variant" reward is exactly SPCT's rule-based RL reward and uses *pairs with known assay outcomes*, so it is a natural fit for DMS/fitness data). **Novel**: SPCT trained on deep-mutational-scanning pairs, reward = "identify the higher-fitness variant" with rubric text, as a reusable reward critic across targets.
6. **Keep-Routing / Keep-Sampling-Mask logic for bio sequence models**: for MoE or constrained-decoding sequence designers (forced valid-codon tables, amino-acid masks, motif locks, grammar-constrained SMILES/SELFIES), record the *exact* decode-time masks and expert routes and replay them when computing training logprobs; otherwise importance ratios are meaningless when the sampler's support differs from the trainer's. Cheap and directly applicable to any pLM/mol-LM RL stack with constrained sampling. Also use the V3.2 off-policy sequence mask when the async oracle latency forces stale rollouts.
7. **Unbiased-KL + per-domain beta** for protecting a pretrained prior: protein/molecule RL typically collapses to a few high-scoring modes; use the V3.2 importance-corrected K3 and tune beta per task (near-zero for verifiable physics-ish tasks, larger for "naturalness"/diversity).
8. **Specialists then on-policy distillation** (V3.2/V4). Train separate RL specialists per modality or target class (antibodies, enzymes, small-molecule ADMET, DNA regulatory elements) with their own verifiers, then distill into one generalist with reverse-KL OPD (student samples, teachers score) instead of mixing incompatible rewards. Avoids reward interference/hacking in a mixed reward. The V4 trick of caching only teacher last-layer hidden states is relevant if teachers are 100B-scale protein/genomic models.
9. **Environment synthesis at scale** (V3.2/V4.1): take many public tools (ColabFold/AF2, RDKit, OpenMM, Rosetta, docking, FBA models via COBRApy, Snakemake pipelines) and auto-generate hundreds of "hard to solve, easy to verify" tasks with a verification function and a pass@100>0 filter (V3.2). **Novel for biology**: large-scale synthetic *lab-automation protocol* environments (simulated liquid handler / plate-reader / PCR scheduling) where the verifier is a constraint checker (volumes, deck collisions, timing windows), then transfer to the real robot with a few real-world fine-tuning episodes.
10. **Slow/expensive oracle rollouts**: borrow V4's *preemptible rollout service with token-level WAL* and its **length-bias lesson** (restarting preempted long jobs biases data toward short/fast-to-evaluate designs). Same bias occurs when oracle latency correlates with design size (large complexes dock/fold slower); log partial trajectories/job IDs and resume rather than drop, and weight by completion probability. Combine with R1's async design: reward module scheduled asynchronously and overlapped with rollout, so folding/docking queues hide latency.
11. **Agentic bio harness with a bare persistent shell** (from deepseek-harness): a single persistent `bash` tool, 300 s timeout, no history compaction, exact tool outputs, so a model can drive Rosetta/GROMACS/Snakemake/ELN-style CLI tools; add the V4.1-reported hazard list (reward hacking, sandbox escapes, deleting data) to the safety design: read-only mounts for assay data, per-rollout copy-on-write filesystem (DSec's EROFS/overlaybd idea).
12. **Language-consistency reward -> "format of evidence" reward** (R1). The cheap proxy reward is a ratio over tokens; analogous cheap shaping rewards: proportion of generated reasoning in a controlled vocabulary/ontology (GO, EC, SMARTS), or consistency between the textual rationale and the final sequence/structure.
13. **Distillation beats small-model RL** (R1): distill a big RL-trained bio reasoner's verified trajectories into small models for edge/high-throughput use (screening, lab-side planners), rather than RL-ing the small model.

Ideas I consider most novel: 3, 4, 5 (DMS-pair SPCT), 6, 9 (lab-automation env synthesis), 10 (oracle-latency length bias).
